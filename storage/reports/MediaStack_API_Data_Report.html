MediaStack API Data Analysis Report

Understanding the Nature of Article Data Returned by the MediaStack News API
Prepared by: DefinePress Development Team  |  Date: May 17, 2026  |  Subject: Investigation into short article descriptions/content

1. Executive Summary

This report documents the findings of a technical investigation into why article descriptions and content appearing on the DefinePress platform are short (typically 100–300 characters).

Key Finding: The MediaStack News API — which serves as the primary data source for DefinePress — is a headline and summary API. It does not provide full article bodies, full descriptions, or extended content. Each article returned contains only a brief summary (the description field), typically 1–2 sentences long.

This is a limitation of the upstream data provider, not a bug or misconfiguration in the DefinePress platform. The system stores exactly what MediaStack delivers.

2. Investigation Methodology

To verify the exact nature of data coming from MediaStack, we performed the following steps:

  1. Direct API call — Fetched 1 article directly from the MediaStack API endpoint https://api.mediastack.com/v1/news with no transformation or processing.
  2. Full response logging — The raw JSON response was captured and logged in its entirety to storage/logs/laravel.log.
  3. Field-by-field analysis — Every key in the response object was examined for type, length, and content.
  4. Content field search — Checked for the existence of any field that might contain full article text (content, body, full_text, article_body, text, summary).
  5. Database verification — Compared 902 stored articles to confirm description and content columns are identical (both sourced from the same MediaStack description field).

Important: The MediaStack API does not provide any field containing a full article body or extended description. The description field (typically 100–300 characters) is the only textual content available.

6. Database Impact Analysis

This limitation has a direct impact on the DefinePress database. Of the 902 articles currently stored:

Metric Value
Total articles in database 902
Articles where description == content (identical) 902 / 902 (100%)
Average description length 188 characters
Maximum description length 603 characters
Minimum description length 4 characters

This confirms that both the description and content columns in the articles table are populated from the same MediaStack description field. The system does not truncate or shorten any data — it stores exactly what the API provides.

7. How the Data Flows

MediaStack API
     │
     ▼
  GET https://api.mediastack.com/v1/news?access_key=XXX&limit=100
     │
     ▼
  JSON Response (10 fields per article)
     │
     ▼
  MediaStackService::prepareArticleData()
     │
     ├── description  ←  $data['description']   (short summary)
     ├── content      ←  $data['description']   (same short summary — no separate field exists)
     │
     ▼
  articles table (description & content columns contain identical text)

8. Options for Richer Article Content

If full article bodies are required, the following options are available:

Solution Cost Effort Notes
Diffbot ~$0.003/article Low (API integration) Send article URL, get clean content. Handles paywalls. Most reliable option.
Mercury Web Parser Free tier + paid Low (API integration) Open source parser also available. Good for non-paywalled sites.
Self-scraping Free (server costs only) High (build + maintain) Fragile — breaks when sites change HTML. Blocked by many sources. No paywall bypass.
Switch API provider Varies Medium NewsAPI, GNews, etc. Some provide richer content than MediaStack.

9. Conclusion

The short descriptions on DefinePress are NOT a system issue or configuration problem.

MediaStack is a headline news API — it provides headlines, source metadata, and short summaries. It is not designed to deliver full article bodies. The DefinePress platform correctly stores and displays exactly what the API provides.

If full article content is desired, we recommend integrating a content extraction service (such as Diffbot) that can fetch and clean the full article text from the original URL.
